why this is expensive

The agent implemented invariant A (sticky original owner), you reviewed, then inverted to invariant B (latest assignment wins). Every prior test, gate, and _history_gate_reason change became waste. This is not “the model is dumb” — it is a live incident used as a spec, updated in-place, inside a 14k-event tree with 52 children.

Steering message into the same child
You ARE the GPT-5.6-Luna subagent the user requested. Implement your assigned work yourself; do NOT spawn/create new tasks or re-delegate… If you already delegated, ensure exactly one writer per file.

So the orchestration was already fighting itself: parent on mixed Astra/Luna, children told not to spawn, meanwhile 2,237 agent.wait calls month-wide.

6. The cheap giant — proof Luna can carry the marathon

You · 02 Sep
Focus on wikow/modal-poc. Investigate how external research intake endpoints work — external-grokbot, 80 new leads (soon 250). Complete research on all of them and get them to assignable state via repairs, or terminate them so they don’t hang open. Notes in Czech for the reps (except email drafts).

49,016 events, 6,254 tools, 426 errors, 89 compactions, 61 amnesia hits — $25.73. Same class of work as the Astra reassignment threads ($244 / $162). Model choice dominated process choice.

Recommendations

  1. Ban long-lived Astra threads. Use Astra for a bounded hard turn (incident diagnosis, one design fork), then start a fresh Luna/Sol thread with a written spec. Continuing Astra across overnight cache is how $643 of cache-read appeared. The 02 Sep Luna marathon is the template.
  2. One deliverable per thread, named in the first line. “Follow-up machine overview” ≠ “v0426 implementation” ≠ “prod deploy” ≠ “Customer D identity merge.” When the user pastes a new incident, spawn or fork — do not keep stacking onto a 14k-event parent. This is the only way to kill KITCHEN_SINK + RUNAWAY_SESSION.
  3. On “USER CORRECTION” / policy reverse: stop writes. Rewrite the invariant in five bullets, throw away the previous tests that encoded the old rule, then edit. The sticky-owner → latest-assignment flip burned a surgical child and then demanded coordination with another subagent (“Coordinate with Maxwell”).
  4. Pin the parent model to Luna when you ask for Luna subagents. Otherwise the parent keeps an Astra cache warm while children do the cheap work. Thread label ≠ bill.
  5. After compaction, forbid recreational re-reads of CLAUDE.md and the pg.py cluster. Put a 20-line working-set (files + current invariant) in the compact summary / a NOTES.md the agent is told to trust. 194 amnesia hits is the agent reconstructing context it just paid to compress.
  6. Cap writers per file. sales/pg.py (68 edits), leads.tsx (40), email_preparation.py (118 across Luna trees including children). One writer, or a lock in the orchestrator prompt. The steering line you already send (“exactly one writer per file”) should be a hard constraint, not a plea.
  7. Questions get a diagnosis turn, not an edit storm. “How do I filter rejected-by-rep?” → answer with the current predicates, then ask “change it?” The ACTING_ON_QUESTION detector is slightly eager, but the screenshot-retry (“it still shows this!!”) is the cost of skipping that turn.
  8. Ignore idle_gap and most overlong_trace in monthly review. They fired on 58% and 67% of trees — desktop sessions that pause overnight. They are not waste. Keep COMPACTION_AMNESIA, CORRECTION_LOOP, EDIT_THRASH, RUNAWAY_SESSION, UNVERIFIED_COMPLETION.
